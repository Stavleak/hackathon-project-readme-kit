# Hackathon project README kit

Stavleak templates for handing a hackathon prototype to a reviewer who was not part of the team.

Choose a template, copy it into your project and replace the bracketed fields with what you actually checked:

- [English template](README.en.md)
- [Русский шаблон](README.ru.md)
- [Қазақша үлгі](README.kk.md)
- [Demo rehearsal worksheet](demo-rehearsal.en.md)

The templates cover one user task, a reproducible setup route, safe input and expected output, reset steps, reviewer access, limitations, criteria and a check record. They contain fields to complete, not an application or ready-to-run installation commands.

Start with one scenario. Have a teammate follow the instructions without help from the author. Record the observed result and the first blocked step, then repeat the same scenario after a repair allowed by the event's rules. A completed README does not establish that a demo worked or determine a competition score.

The room-filter example is fictional. Replace it if it does not match your project. Keep real participant data, passwords and tokens out of public files. Check someone else's code in a disposable isolated environment without work secrets or host-folder mounts.

Update the README before the final commit. Record the commit identifier and the README permalink in the approved submission record after creating the commit. Saving that identifier inside the same README would create a different commit.
